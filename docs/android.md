# Android 客户端

Android 使用 Jetpack Compose, 与 macOS 和 Windows 共用 Rust 协议核心与局域网交接状态机. 手机界面提供耳机, 设备, 交接, 设置和活动五个入口.

## 连接与控制

先在系统蓝牙设置中配对耳机, 打开应用后授予蓝牙权限. Android 12 及以上使用附近设备权限, 较旧系统使用位置权限授权蓝牙访问. 授权前可以浏览页面和调整应用外观.

设备页扫描已配对的漫步者耳机, 也可连接上次设备或输入蓝牙地址. 启动时若系统已经连接耳机音频, 应用会尝试一次接入其控制通道; 不会在心跳中反复抢回连接. 被其他组成员持有的耳机会先请求交接. 当前 Android 控制通道使用经典蓝牙, 不提供尚未实现的 BLE 连接入口.

耳机页分别显示控制通道和系统音频状态. 断开控制通道不会主动释放系统音频. 控件按所选机型显示, 不认识的机型可以在高级设置中手工选择. 电量和设置在收到回报前显示未知, 应用不会把指令发送成功视为设置已生效. 输入框保留未提交草稿, 应用后等待耳机回报确认; 可以撤销草稿并重新读取.

环境声强度, 提示音量和定时关机使用各自的协议范围. 提示音量不是系统媒体音量. 初始化与读取信息只发送查询, 不设置媒体音量. LDAC, 关机, 重新配对和恢复出厂等操作会先说明影响并确认.

## 跨设备交接

各端加入完全相同的组名, 保持处于同一局域网且应用运行. 入组后显示本次加入的组名, 即使不记住组名也能查看和复制. 记住组名与启动时自动加入是独立选项, 默认不自动入组.

点击持有耳机的成员请求接管, 页面展示请求, 等待释放, 连接音频和最终结果. 请求发出不表示接管完成; 只有系统确认实际音频连接后才声明本机持有. 正在连接或无法取得音频状态时, 不会误报连接或释放成功. Android 的自动音频连接依赖系统能力, 失败时可以打开系统蓝牙设置连接, 再重试控制连接或交接.

退出组会清除当前组名与成员列表. 取消记住组名只清除保存内容, 不会退出当前组.

## 设置与活动

设置页提供跟随系统, 浅色和深色主题, 组名记忆与自动入组, 服务启动与停止, 系统设置入口及应用和核心版本. 设置带 `schemaVersion`, 旧版保存的组名通过独立迁移读取. 保存失败在设置页提示.

活动页保留本次进程最近 200 条操作和结果, 可以清空. 编码和原始帧解析放在折叠诊断区, 不需要连接耳机. 原始指令发送需要再次确认. 关键操作同时通过 Android 日志记录, 轮询不会逐帧刷屏.

会话与事件读取属于应用进程, 切换页面或旋转屏幕不会重复创建. 应用进程被系统结束时服务停止; 当前没有前台常驻服务, 不能保证系统回收进程后继续接管. 在设置中主动停止服务会退出组, 关闭控制通道并释放蓝牙资源, 返回页面不会擅自重新启动.

## 构建

使用项目已有的 Android SDK, NDK, Gradle, Rust Android 工具链和 `cargo-ndk`:

```shell
just android build
just android install
just android run
```

`build` 同时编译 Kotlin 与 JNI 核心. 更新界面源码时也需要带上对应的 `libedifier_ffi.so`, 退出组等 JNI 接口必须与应用匹配.
