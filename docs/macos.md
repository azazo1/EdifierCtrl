# macOS 桌面端

EdifierCtrl 使用 SwiftUI 界面和 AppKit 窗口/菜单栏, 通过 Rust C ABI 复用 Android, Windows 和 Linux 的耳机协议与局域网交接状态机. 最低系统版本为 macOS 13.

## 构建和运行

需要 Xcode 命令行工具, Rust 和 just. 在仓库根目录执行:

```shell
just macos build
just macos run
```

`build` 生成 `target/macos/debug/EdifierCtrl.app`, 内含 Rust 动态库, 蓝牙/本地网络权限说明和应用图标. 可从 Finder 打开, 也可通过 `run` 在终端运行. `Ctrl+C` 会停止后台服务并保存设置后退出.

独立调试实例使用专用数据和日志目录:

```shell
just macos debug
```

数据保存在 `target/edifierctrl-debug/`, 不影响日常实例. `EDIFIER_DATA_DIR` 和 `EDIFIER_LOG_FILE` 可分别指定数据目录和日志文件, `EDIFIER_LOG_LEVEL=debug` 启用详细日志.

## 连接与控制

1. 打开耳机, 在 macOS 蓝牙设置中完成配对.
2. 打开设备连接页并刷新列表. 自定义名称的耳机可以通过 "显示所有设备" 找到.
3. 点击连接, 应用读取电量和可用设置. 控制通道与系统音频分别显示状态.
4. 在我的耳机页选择机型档案. 功能由 Rust 档案提供, W820NB 等机型只显示其支持的选项.

降噪和音效点击后发送. 滑块先保留草稿, 点击应用才发送, 撤销恢复最近收到的值. 界面中的电量和已选状态以耳机回报为准; 发出命令不等同于设备已经应用. 不同固件可能不回报全部设置.

"断开控制" 只关闭控制通道, 保留系统音频. 释放主机, 关机, 重新配对和恢复出厂操作都需要确认. LDAC 选项修改耳机端偏好, 不会让 macOS 获得 LDAC 音频输出能力.

## 跨设备交接

耳机先在各台设备上分别配对. 所有客户端处于同一局域网并使用完全相同的组名. 在目标设备上选择当前持有耳机的成员, 点击接管. 界面显示请求, 释放原连接, 建立新连接和结果.

组名可保存在当前数据目录的 `group-secret.json` 中, 正式, 调试与 fake 实例各自保存. 开启自动加入后, 下次启动恢复交接组. 关闭窗口不影响成员发现和交接响应; 退出交接组会停止该组服务, 本机控制仍可使用. 在另一台设备上发起接管即可让本机释放耳机.

交接使用现有局域网协议, 不需要云端账号. 需要允许应用访问本地网络, 并避免 Wi-Fi 的客户端隔离阻断成员发现. 原理见 [组协议](group.md).

macOS 使用 IOBluetooth 建立经典蓝牙控制通道, 以 CoreAudio 的实际蓝牙输出端点确认音频可用. 显式接管会先通过公开 API 异步发起蓝牙连接, 在有界等待内核验音频端点, 成功后将耳机设为默认音频输出; 仅加入组或查询状态不会切换输出. macOS 公开 API 无法保证让所有离线耳机自动建立 A2DP, 系统自动重连也可能干扰交接. 确认失败时应用会显示失败或待确认, 可在系统蓝牙设置中连接后再试. Android 隐藏 A2DP API, Windows 音频端点和 Linux BlueZ 行为也需要在相应系统及耳机上验证.

## 后台使用

- 菜单栏图标左键显示并聚焦唯一主窗口, 右键打开快捷菜单.
- 关闭窗口隐藏应用并继续服务, 可设置 Dock 图标是否跟随隐藏.
- 可设置启动时隐藏主窗口. 窗口记忆普通尺寸及缩放状态, 不恢复位置或全屏.
- 同一数据目录只运行一个实例; 再次启动唤起已有窗口. 调试实例可与日常实例并行.
- 完全退出使用应用菜单, 菜单栏右键菜单或 `Cmd+Q`.

应用设置中可切换详细日志并打开日志位置. 文件日志按日期或 5 MiB 轮转, 最多保留 10 份归档. 组名不会写入日志.

## 分发和更新

```shell
just macos dist
just macos fake-dist
```

分发产物位于 `target/macos/dist/`, 包含当前 CPU 架构的 DMG 和 `SHA256SUMS`. 命名为 `EdifierCtrl-<version>-macos-<arch>.dmg`, 架构为 `aarch64` 或 `x86_64`. 公开 Release 必须包含对应安装包与摘要文件. 无正式 tag 的构建显示 `dev-build`, 不提示更新.

`fake-dist` 复用相同打包路径, 版本注入为 `v0.0.0`, 产物文件名带 `-fake`, 数据目录隔离, 不用于上传 Release. `EDIFIER_CODESIGN_IDENTITY` 可指定签名身份; 未指定时使用本地 ad-hoc 签名, 公开分发仍需要 Developer ID 签名与公证. 不会自动创建 tag 或发布 Release.

应用按 GitHub Release 精确匹配架构和 SHA256SUMS, 支持续传及整包校验. 下载结束后保持当前应用运行, 只有点击重启并更新才替换 bundle. 安装助手保留日志并在替换失败时尝试回滚. 从 DMG 内或裸二进制启动时, 通过打开安装包手动安装. 安装到真实目录后的完整更新链路需要使用实际发布包验证.

## 验证

```shell
swift test --package-path apps/macos
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Swift 测试覆盖跨平台地址格式, 设备切换时清理旧状态, 断线后丢弃迟到通知, 控制/音频状态分离, 更新版本比较, 校验和与安装路径约束. Rust 测试使用模拟传输验证释放确认, 超时, 并发交接和会话清理; 这些测试不能代替真实耳机的跨设备联调.
